# Pull requests and preview builds

Polysome uses pull requests as the only path into `main`. GitHub Actions checks
the package and Astro frontend, while Cloudflare Workers Builds uploads every
pull-request branch as a Worker version with a stable `workers.dev` preview URL.

The frontend is statically generated by Astro. It does not use the Cloudflare
Astro adapter because it has no server-rendered routes; Wrangler serves the
generated files directly as Worker static assets.

## Repository configuration

In the GitHub repository, create a branch ruleset targeting `main`:

1. Require changes to be made through a pull request.
2. Require the `CI / check` status check before merging.
3. Require branches to be up to date before merging.
4. Block force pushes and branch deletion.
5. Optionally require an approval when another regular reviewer is available.

Do not require an approval in a single-maintainer repository unless a bypass is
configured; otherwise release and dependency pull requests can deadlock.

Release Please also merges through a pull request, so package releases follow
the same checks as implementation changes.

## Cloudflare Workers Builds setup

This is a one-time dashboard operation:

1. In Cloudflare **Workers & Pages**, create or select the `polysome` Worker.
2. Open **Settings → Builds** and connect the
   `teamdandelion/polysome` GitHub repository.
3. Set the production branch to `main` and the root directory to `/`.
4. Set the build command to `npm run build:demo`.
5. Set the production deploy command to `npx wrangler versions upload`.
6. Enable non-production branch builds and use
   `npx wrangler versions upload` as their deploy command as well.
7. Confirm that Worker preview URLs are enabled.

Using `versions upload` for `main` intentionally creates a previewable version
without promoting an independent Polysome production deployment. The canonical
artwork remains `dandelion.art/art/polysome`.

For each pull request, Cloudflare will post:

- a commit-specific preview URL; and
- a stable branch alias that continues to point to the newest commit.

Preview aliases have the form
`<branch-alias>-polysome.<account-subdomain>.workers.dev`. They are public by
default. Protect the Worker's preview URLs with Cloudflare Access if previews
should not be generally visible.

The GitHub integration stores Cloudflare credentials on Cloudflare's side, so
this native setup does not require Cloudflare API secrets in GitHub Actions.

## Local verification

```sh
npm run dev           # Astro development server
npm run check         # package, Astro, build, and Wrangler validation
npm run preview:demo  # serve the production build with Wrangler
```

To manually upload a named preview after authenticating Wrangler:

```sh
npm run build:demo
npx wrangler versions upload --preview-alias staging
```

The checked-in [`wrangler.jsonc`](../wrangler.jsonc) explicitly enables preview
URLs and keeps the Worker name stable across local and Cloudflare builds.
